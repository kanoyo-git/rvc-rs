# RMCPE для извлечения F0

На 33 отложенных записях сольного пения RMCPE правильно определил высоту или отсутствие голоса в **93,50%** кадров. У RMVPE получилось 88,94%, у FCPE — 87,39%. Основной выигрыш пришёлся на согласные, дыхание и паузы, где аннотатор оставил F0 равной нулю. RMCPE пропустил 332 из 76 591 размеченных озвученных кадров, RMVPE — 123, FCPE — 57. Все три прогноза получены через `rvc extract` на арендованной RTX 4090. [Результаты по каждой записи](rmcpe/vocadito-results.json)

## Как использовать

Укажите `--f0-method rmcpe` в `rvc extract`, `rvc infer`, `rvc cover` или `rvc realtime`. В Studio метод доступен для извлечения признаков, обычной конверсии, кавера, реального времени и аугментации слоя. В VST он доступен в параметре F0 Method. CLI и Studio загружают `rmvpe.pt` и пакетный `fcpe_c_v001.pt`. Для VST разместите эти веса в выбранном корне RVC. Обзор пакетного FCPE и его отличий от модели в статье находится в [разборе FCPE](FCPE.md).

При повторной экстракции проект проверяет метод, версию расчёта, настройки озвученности, размер и время изменения весов и исходного WAV. После смены метода он пересчитывает F0, сохраняя готовые эмбеддинги. Одна дорожка даёт три файла для сырой, непрерывной и дискретной F0. Для полностью глухой дорожки они также создаются. Прерывание смены метода оставляет метку до завершения следующей экстракции F0. У старого эксперимента без метаданных явный запуск экстракции заново вычисляет F0. [Кэш экстрактора](../crates/rvc/src/model/extract.rs) · [Загрузка тренировочного эксперимента](../crates/rvc/src/model/train_data.rs)

## Устройство метода

1. RMVPE и FCPE строят карты вероятностных оценок для монофонического сигнала 16 кГц. Каждые 10 мс RMCPE получает по 360 значений из каждой модели. Оси частот различаются. RMVPE использует свой шаг 20 центов, а FCPE — таблицу частот своего чекпойнта. Центр окна FCPE смещён на 5 мс. Перед выбором пиков RMCPE интерполирует карту FCPE на временную сетку RMVPE.
2. Каждая сеть предлагает до двух локальных максимумов. Частота пика уточняется по соседним бинам. Сила свидетельства нормируется относительно собственного порога детектора. От сильнейшего пика каждой сети также проверяются половинная и удвоенная частоты в пределах 32–1980 Гц.
3. Для каждого кандидата исходная волна проверяется на повторение с дробным периодом в окне 80 мс. Дополнительная проверка половинного и третьего периода подавляет субгармоники, когда более короткий период объясняет почти весь сигнал. Переход на октавную альтернативу без поддержки сети требует особенно высокой периодичности.
4. Динамическое программирование выбирает путь через частоты и отдельное состояние U. Цена смены ноты зависит от интервала в октавах, цена перехода V/U конечна. Для длинной записи сети работают участками по 30 с с контекстом до 1 с с каждой стороны. Путь по кандидатам декодируется сквозь границы участков.
5. На границах согласных и гласных ещё раз проверяется периодичность выбранной частоты в коротком окне 40 мс. Для тихого фрагмента рядом с громким требуется более явное подтверждение периода. Согласие обеих сетей снижает этот порог. Если RMVPE подтверждает ту же ноту в пределах 75 центов, выходная частота уточняется в логарифмической шкале. Выход совместим с RVC и содержит `floor(samples / 160) + 1` значений в герцах с нулём на U. [Реализация RMCPE](../crates/rvc/src/model/rmcpe.rs) · [Карты RMVPE](../crates/rvc/src/model/rmvpe.rs) · [Карты FCPE](../crates/rvc/src/model/fcpe.rs)

## Пение с разметкой Vocadito

В версии v3 есть 40 записей 29 исполнителей. Аннотатор вручную исправлял ошибки F0 и V/U после pYIN. Разбиение зафиксировано по SHA-256 идентификатора певца. Семь записей пяти исполнителей использованы для выбора порога и уточнения высоты. Параметры заморожены до оценки остальных 33 записей 24 исполнителей. Обе нейросети использовали поставляемые проектом веса. Проверить, встречался ли этот публичный корпус в исходном обучении этих весов, по опубликованной информации не удалось. | Общая точность, % | 88,936 | 87,394 | **93,503** |
| F0 в пределах ±50 центов от всех размеченных V, % | 98,189 | 97,403 | **98,342** |
| Ложная озвученность от всех размеченных U, % | 28,463 | 31,427 | **15,597** |

Во всех строках сравниваются одни и те же 117 324 отметки времени, включая 76 591 V и 40 733 U. Частота сравнивается с ближайшим центром нативного кадра. В общую точность входят правильные U и озвученные кадры с ошибкой до 50 центов. Парный bootstrap с 5000 пересэмплирований по исполнителям дал прирост общей точности к RMVPE **+4,57 п.п.** с 95%-м интервалом от +3,11 до +6,33, к FCPE **+6,11 п.п.** с интервалом от +5,20 до +7,20. Для точности высоты на озвученных кадрах интервал разницы с RMVPE составляет от −0,12 до +0,46 п.п. [Счётчики, интервалы и разбиение](rmcpe/vocadito-results.json)

## Стоимость и границы применимости

При уже извлечённых эмбеддингах 40 файлов через CLI заняли 31,68 с для RMVPE, 6,95 с для FCPE и 37,30 с для RMCPE. Замер включает загрузку весов, вычисление F0 и запись файлов. На машине параллельно шло дообучение, замер проведён один раз. Результат описывает именно этот запуск.

В реальном времени измерялся полный прогон модели RVC на блоках входа по 250 мс. После трёх прогревочных блоков медиана и p95 по 12 блокам составили 105,16 и 191,06 мс для RMVPE, 103,71 и 175,40 мс для FCPE, 114,50 и 195,13 мс для RMCPE. Максимум для RMCPE составил 202,54 мс. В тесте использовался рабочий поток модели с заранее записанным сигналом. Задержка конкретного аудиодрайвера требует отдельного измерения. Офлайн-конвертация той же записи через RMCPE дала конечный сигнал mono 40 кГц длительностью 33,2 с. [Времена каждого блока](rmcpe/runtime.json) · [Сценарий реального времени](../crates/rvc/examples/realtime_benchmark.rs)

Качество измерено на одноголосном пении и отдельных искусственных сигналах. Для хора, аккомпанемента с другим основным тоном, скрима, сильно придыхательного вокала и тихой речи нужны отдельные контрольные записи. Глухая разметка и очень слабая периодичность остаются источниками ошибок. Обе сети используют будущий контекст внутри окна. В потоке длина и расположение окна ограничивают результат, особенно в начале и в конце нот.

RMCPE управляет высотой и озвученностью генератора. Сходство тембра с целевым датасетом оценивается после синтеза, по отдельным референсам исполнителей и прослушиванию.

## Воспроизведение

Нужны `ffmpeg`, Python 3.11+ с NumPy, CLI с inference и каталог ресурсов проекта. Скачайте архив v3 по ссылке авторов. Скрипт сверяет его MD5, переводит WAV в mono PCM 16 кГц и без интерполяции V/U сохраняет счётчики по всем трекам. Для измерения времени укажите новую рабочую папку.

```sh
python bench/rmcpe/vocadito.py --archive vocadito.zip --work results/vocadito \
  --rvc /path/to/rvc --root /path/to/project --device cuda:0
python bench/rmcpe/compare.py results/vocadito results/vocadito-results.json
python bench/identity/fcpe_probe.py --rvc /path/to/rvc --root /path/to/project \
  --device cuda:0 --methods rmvpe fcpe rmcpe
python bench/rmcpe/cache_check.py --rvc /path/to/rvc --root /path/to/project
```

Для воспроизведения задержки подставьте собственный голосовой чекпойнт RVC с F0 и 40 кГц. Исходный эксперимент использовал локальную модель. Время зависит от архитектуры голоса, аудиоблока, системной нагрузки и оборудования.

```sh
ffmpeg -v error -i results/vocadito/waves/vocadito_1.wav -f f32le -ac 1 -ar 16000 input.f32
cargo run --release -p rvc --example realtime_benchmark -- --root /path/to/project \
  --model /path/to/voice.pth --input input.f32 --device cuda:0 --f0-method rmcpe --warmups 3 --blocks 12
```
